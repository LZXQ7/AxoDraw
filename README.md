# AxoDraw · 公开可验证的抽奖与随机排序

抽奖最怕的就是「凭什么相信你没作弊」。AxoDraw 把随机信标、名单承诺、算法和验证结果全部公开，让参与者能够复算并发现不一致；它同时明确说明仍然存在的部署方信任边界。

除了随机抽奖，它还支持**随机排序**与**分组随机排序**。两者有两条路径：

- **即时工具（默认）**：「随机排序」页面，粘贴名单、点一下就在浏览器本地打乱，不需要发起、不需要等待，也不产生公开记录；
- **可验证记录（接口）**：创建时指定 `mode = shuffle` 或 `group`，与抽奖共用同一套 drand 公开信标、无偏洗牌与公开承诺，结果人人可复算。

> 🎯 使用地址：**<https://draw.axlmc.org>**（黑白极简风格，无需注册）

## 三种结果模式

| 模式 | 结果 | 参数 | 入口 |
|---|---|---|---|
| **随机抽奖** | 取无偏洗牌结果的前 N 项作为中奖名单 | 中奖人数 N | 「发起」页面（可验证） |
| **随机排序** | 输出完整的随机顺序，全部参与值不重不漏 | 无 | 「随机排序」页面（即时）／接口 `mode=shuffle`（可验证） |
| **分组随机排序** | 先随机排序，再按顺序连续均分成若干组（各组人数相差不超过 1，组内顺序同样随机） | 分组数 G | 「随机排序」页面填分组数（即时）／接口 `mode=group` + `groupCount`（可验证） |

可验证路径下，模式与分组数都会写进创建时的公开承诺，事后无法悄悄改写。

## 即时随机排序（无需发起）

打开「随机排序」页面即可：粘贴名单（或上传 `.txt` / `.csv`）→ 需要分组就填分组数 → 点「开始随机排序」。结果为完整随机顺序或分组卡片，可一键复制文本、也可以点「再排一次」换一组顺序。

- 随机源是浏览器的 `crypto.getRandomValues`，洗牌规则与 deterministic-v2 相同：Fisher–Yates + 拒绝采样，没有取模偏差；
- 全部计算在本地完成，名单与结果都不会上传服务器，自然不会留下公开记录；
- 因为不涉及第三方信任，这里也不需要信标、承诺、截止时间和人机验证。

## 三步搞定一场抽奖

**1. 发起抽奖**

打开「发起」页面，填好：

- 抽奖标题；
- 截止时间（按北京时间）；
- 中奖人数；
- 参与值——一行一个，也可以直接上传 `.txt` / `.csv` 文件。

创建时会自动做人机验证，不需要注册账号。

**2. 分享链接**

创建成功后你会拿到三样东西，其中两样可以公开：

- **公开链接** —— 直接发给参与者；
- **抽奖编码**（形如 `AXO-2F0A7C16B491E3D8`）—— 在首页输入即可查询结果；
- **管理链接** —— ⚠️ **只显示一次，请立即保存**。截止前用它修改参与值，截止后 10 分钟，用它点「立即开奖」。

**3. 开奖并核对**

开奖后，中奖名单、随机数、签名、参与值承诺和摘要会公开展示。系统会自动重新获取目标轮次的 drand 信标，核验签名并复算结果；任何人也可以照着页面记录独立重算。

## 为什么可以相信它

- **随机数不来自网站**：来自 drand 公开随机信标，每 3 秒全网发布一轮。服务端固定 quicknet 的 chain hash 与公钥，并验证该轮 BLS 签名。
- **用哪一轮随机数由截止时间决定**：跟谁点、什么时候点「生成结果」完全无关。
- **无偏确定性洗牌**：`deterministic-v2` 使用 HMAC-SHA-256 计数器生成独立随机块，再用拒绝采样消除取模偏差。固定输入只会得到一个结果，同时名单原始顺序不会改变每项概率。
- **同一顺序，三种解释**：抽奖取前 N 项、随机排序取完整顺序、分组模式把顺序连续均分。模式与分组数都在承诺里，事后改写模式会让承诺、digest 与结果全部对不上。
- **公开名单承诺**：每次创建或截止前修改名单时，系统都会重算包含全部参数的 `entriesCommitment`（非抽奖模式还把 `mode` 与 `groupCount` 纳入承诺）。参与者可在截止前保存它，并在出结果后核对。
- **真实验证**：验证接口会检查目标轮次、drand 签名、名单承诺、结果模式、算法版本、digest、结果名单（分组模式下还包括每个分组），而不是只检查“是否存在结果”。

需要说明的是，**即时排序工具不提供这些保证**：它用浏览器本地随机数，没有信标、承诺与公开记录，用起来最快，但不适合需要第三方复核的场景。

想看逐步图解？网站上的「运行原理」页面讲得很细；也可以直接查示例 **`AXO-7K4M`**（抽奖）、**`AXO-7K4S`**（可验证随机排序记录）、**`AXO-7K4G`**（可验证分组记录）。

## 常见问题

| 问题 | 回答 |
|---|---|
| 需要注册或登录吗？ | 不需要，发起、查询和随机排序都不需要账号。 |
| 随机排序要发起吗？ | 不用。打开「随机排序」页面，粘贴名单点一下即可；不需要截止时间、管理链接和人机验证。 |
| 即时排序的结果能被别人复算吗？ | 不能，它是纯本地工具，随机源是浏览器 crypto，没有公开信标与承诺。需要可复算的排序或分组时，用接口以 `mode=shuffle` / `mode=group` 创建记录。 |
| 管理链接丢了怎么办？ | 丢了就没人能改参与值、也没人能开奖。结果始终公开，但没人触发就不会产生结果，请务必保存好。 |
| 截止前还能改什么？ | 只能用管理链接改参与值。标题、截止时间、中奖人数创建后不可修改。 |
| 分组是怎么分的？ | 先随机排序，再按顺序连续切分：各组人数相差不超过 1（前面的组先多 1 人），组内顺序也来自同一次随机排序。由于洗牌是均匀随机的，这等价于把参与值均匀随机分配到各组。 |
| 随机排序会漏人吗？ | 不会。排序与分组结果里全部条目都会出现且只出现一次；可验证记录中 `winners` 字段就是完整随机顺序。 |
| 会自动开奖吗？ | 不会。需要持有管理链接的人在截止 10 分钟后手动触发。 |
| 参与值有重复怎么办？ | 创建时可勾选「自动去重」；不勾选的话，重复的每一行都算一张独立票。 |
| 按哪个时区？ | 全部按北京时间（UTC+8）。 |
| 结果还能改吗？ | 正常接口不允许。写入后不能再次生成，参与值在截止后锁定；验证接口会检测记录与承诺不一致。 |

## 信任边界

`entriesCommitment` 是公开、可保存的快照哈希，但项目目前没有接入独立的外部时间戳或透明日志。因此：

- 在截止前保存了承诺的参与者，可以检测服务端后来改动名单或参数；
- 只在开奖后第一次访问页面的人，仍需信任部署方没有同时改写数据库记录和承诺时间；
- GitHub 上的源码也不能单独证明线上部署的正是同一份构建。

高价值场景应把截止前的 commitment 写入独立、只追加且带可信时间戳的公开日志。项目不会把数据库内的哈希宣传成“完全无需信任运营者”。

> 兼容性说明：旧的 `deterministic-v1` 结果仍能复算，但该版本的 LCG 洗牌存在显著顺序偏差，验证接口会把它标记为不公平；所有新抽奖只使用 `deterministic-v2`。

### deterministic-v2 精确规范（三种模式共用）

1. 按固定键顺序执行 `JSON.stringify` 得到 `canonicalLottery`：
   - 抽奖模式（`mode` 缺省，即旧记录）：`version`（固定为 `axodraw-commitment-v1`）、`code`、`title`、`description`、`deadline`、`winnerCount`、`duplicatePolicy`、`entries`；
   - 随机排序 / 分组模式：`version`（固定为 `axodraw-commitment-v2`）、`code`、`title`、`description`、`deadline`、`mode`、`groupCount`（排序模式为 `null`）、`winnerCount`、`duplicatePolicy`、`entries`。
2. `commitment = "sha256:" + SHA256_UTF8(canonicalLottery)`。
3. `digestHex = SHA256_UTF8(randomness + "|" + commitment + "|deterministic-v2")`。
4. 对从 `0` 开始的每个 64 位大端计数器生成 `block = HMAC_SHA256(hexToBytes(digestHex), UTF8("axodraw-deterministic-v2\0") || uint64be(counter))`，其中 `\0` 表示一个 NUL 字节。
5. Fisher–Yates 每一步令 `bound = i + 1`、`limit = 2^256 - (2^256 mod bound)`；当 `uint256be(block) >= limit` 时丢弃该块并使用下一计数器，否则 `j = uint256be(block) mod bound`，交换 `entries[i]` 与 `entries[j]`。
6. 洗牌完成后按模式解释这个顺序：
   - 随机抽奖：取前 `winnerCount` 项；
   - 随机排序：取完整顺序（`winners` 即全部参与值的随机顺序）；
   - 分组随机排序：取完整顺序并按 `groupCount` 连续均分——令 `base = ⌊n / g⌋`、`rem = n mod g`，前 `rem` 组 `base + 1` 人，其余组 `base` 人，写入 `groups`。

测试目录包含固定跨实现向量、旧版兼容向量，以及随机排序 / 分组模式的覆盖与防篡改用例。

> 即时排序工具复用同一套 Fisher–Yates + 拒绝采样规则（实现见 `src/lib/shuffle.ts`），只把随机源换成浏览器的 `crypto.getRandomValues`：每一步下标同样均匀、没有取模偏差，但随机数本身不可复算。
